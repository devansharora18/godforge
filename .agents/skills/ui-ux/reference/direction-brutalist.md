# Direction — Brutalist

**Content fit:** developer tools, open source, infrastructure, anything sold to people who distrust marketing.
**Not when:** the audience is non-technical, or trust must be conveyed through polish.

## Skeleton

```
┌──────────────────────────────────────────┐
│ WORDMARK              [DOCS] [GITHUB]    │
├──────────────────────────────────────────┤
│ A HEADLINE THAT DOES NOT APOLOGISE       │
│ ─────────────────────────────────────    │
│ ┌ command ─────────────────────────────┐ │
│ │ $ real command                       │ │
│ └──────────────────────────────────────┘ │
├──────────────────────────────────────────┤
│ 01 / capability        plain description │
│ 02 / capability        plain description │
└──────────────────────────────────────────┘
```

Sections: boxed hero → ledger of capabilities → raw table → colophon. Borders do the layout work.

## Type

- Display: Archivo Black, Anton, Space Grotesk at heavy weight, or a mono at 48–96px.
- Body: the same family at 15–16px, or a plain grotesk. Mono for labels, commands, and metadata.
- Uppercase allowed for navigation and labels, never for paragraphs.

## Color

- Black field or bone paper, no mid-greys except rules.
- One hazard accent: acid yellow, safety orange, or signal green. It marks the active thing.
- Links are underlined and the underline is visible, always.

## Texture

Visible borders on everything, hard 0px corners, diagonal hatching or a grid overlay at low opacity, oversized ASCII separators.

## Motion

Almost none. Instant hovers (0–80ms), no easing theatre. One hard cut on load is better than a fade.

## Signature

An exposed structure: numbered rows, visible rules, a real command with real output, or a table that looks like a config file.

## Avoid

Rounded corners, soft shadows, gradients, glass panels, stock photos, friendly illustrations, emoji, anything described as "delightful".
